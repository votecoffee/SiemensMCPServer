# Classic script and trigger analysis

`analyze_script_triggers` inventories supplied classic WinCC XML without executing scripts or opening TIA. Discover its schema, then use `siemens_offline_analyze` with `operation: "analyze_script_triggers"` and `input: JSON.stringify(request)`. The request contains `resources: [{hmiId, path, xml}]`, optional `coverage`/`schedulerEvidence`, and `view`, `offset`, `maxItems`. Paths identify evidence and are never opened. Native candidate workers expose the shared engine through `tia_read_extension` (`module: "comfort"`, once-serialized `argumentsJson`); inspect the live generation first.

Views are `scripts`, `registrations`, `calls`, `dependencies` and `diagnostics`. Page through `page.hasMore`. Original resource/code hashes, XML/XPath locators and script lines retain provenance. Analysis hashes are stable across views/resource order. Use distinct HMI IDs and exports from one snapshot.

Literal `SmartTags("name")` and direct `HMIRuntime.Tags("name").Read`/`.Write` patterns and exported-script call candidates are inspected. This lexer is not a compiler or control-flow proof. Computed names, handles, shadowing, external members, missing/structured code and ambiguous exports remain unknown/candidates. Explicit native Script/VBScript links differ from function-name matches, which do not prove native binding.

Caller-reported category coverage uses `complete`, `partial`, `notSupplied` or `unsupported`; omitted categories remain `unknown`. Include scripts, tag tables, screens, permanent areas, templates, popup/slide-in screens and available cycle/task exports. Supplied scheduler/deployed-image/observation notes are hashed but unverified. Continuous acquisition plus `ChangeValue` does not prove periodic callback execution.

Diagnostics identify missing demonstrated trigger reads, repeated display-work candidates, unproven periodic reconciliation, conversion/loop review and opaque code. Configured handler counts are not measured invocation rates; possible queue pressure is not proven overflow. Empty-string/zero/visibility-false write sites do not prove a complete reachable clear path. Review valid-zero/replacement, quality loss, text/visibility relationships and callback execution. Cached-string cleanup cannot repair an unexecuted callback. Future coalescing needs serial/commit-token coherence and bounded retries; controller-specific banner contracts stay with their owning workflow.

Bounds include 1000 resources, 256 scripts, 10,000 registrations, 20,000 call/dependency sites, 20,000 XML elements/document, depth 64, 200,000 total elements and 8 MiB aggregate XPath locator characters. Code is limited to 262,144 characters/50,000 tokens per script; pages contain 1–200 rows. DTDs and duplicate IDs/resource identities are rejected. Direct offline input/result caps remain 4 MiB UTF-8 JSON/1 MiB. Splitting resources changes completeness. Static/model/MCP tests do not establish native import, deployed runtime or scheduler acceptance.
