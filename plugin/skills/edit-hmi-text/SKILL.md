---
name: edit-hmi-text
description: Inspect and edit Comfort/classic or Unified HMI engineering objects, text lists and screens through local Siemens TIA Portal Openness, including supported object creation and native resource import/export. Use for an open TIA engineering project; excludes running-device control.
---

Use the Siemens TIA Openness tools to work directly with the selected engineering project. Preserve the user's authorized scope across the workflow.

Prioritize Comfort/classic on V15.1; Unified follows with its version-specific limits. For a Comfort screen/resource caption, layout or configuration change, use `hmi_read_classic_resource` on an exact path from the object browser. Preview existing scalar XML changes with `hmi_preview_classic_xml_edits`, supplying `xPath`, exact old/new values and the resource fingerprint. Select by structure/stable names rather than volatile export IDs. Other languages and companion images are preserved. Apply the matching plan with `hmi_apply_classic_xml_edits`; native readback must match. Use reviewed native import for structural XML changes, and retain the specialized text-list workflow for translation-only edits.

For object operations beyond specialized text-list/caption editing, start with `hmi_read_object` and an empty path. Follow returned paths and inspect editable flags, types, enum choices, creation arguments and import/export support. Preview attribute changes with `hmi_preview_object_edits`, native creation with `hmi_preview_create_object`, or explicit member deletion with `hmi_preview_delete_object`. Apply the reviewed plan with `hmi_apply_object_plan`. Parent/services navigation and arbitrary CLR values are excluded; do not infer support from a device family alone. Existing classic cycles remain protected. A null scalar uses `<null>` as its expected value. Generic multilingual Text is raw native markup; prefer the dedicated caption workflow to retain simple styling.

For transfers, use `hmi_export_objects` on a subtree or empty path for the API-visible HMI. Preserve native files and sidecars. `hmi_preview_import` stages one resource/companion set into an import-capable composition. `hmi_preview_import_bundle` stages an indexed bundle in dependency order and recreates supported folder hierarchy. Review import targets and replacement scope; Unified directory imports require overwrite=true. Project graphics are shared across the project. Failed/incomplete bundles are rejected, and metadata-only objects cannot be restored through import. Generic imports report native acceptance and after-export evidence with content equality not asserted. Read [feature coverage](../../FEATURE-COVERAGE.md) when choosing a route for tags, scripts, alarms, screen objects, bindings or bulk transfers.

Call `tia_list_versions` and, if needed, `tia_select_version`, then inspect `tia_get_api_capabilities`. Enumerate processes with `tia_list_processes`. Select the process and exact project path from the user's request and discovery results. If several projects are plausible, ask which one before attaching. Never choose the first project automatically. Attach using both process ID and expected path, then use the returned HMI ID, family and capability flags. The installed V19 API has Unified screen support but no Unified text-list route. Never fall back to classic XML for a Unified target or infer capability solely from the TIA version label.

Read the requested text list with `hmi_read_text_list`. Each value has an entry selector, culture, text, and editable flag. Pass its fingerprint and exact old text to `hmi_preview_text_edits`. Selectors are numeric strings or `Default`. This adapter edits existing plain-text SingleValue entries and cultures while preserving other languages/configuration. Structure changes or complex content require an explicitly scoped native resource import where the selected API supports it.

For Unified text lists, use the same text-list tools only when the target reports support for the paired-YAML API. Review the native import scope: Siemens recreates all exported user lists, even though this adapter changes only selected translation scalars and preserves the configuration. Keep both YAML files together and preserve ordered language slots. Shared references, unsupported format versions or incomplete exports stay blocked. A documented newer API route is not evidence that a V21 build or a native trial has passed.

For Unified screens, discover exact paths with `hmi_list_screens` and `hmi_list_screen_items`. Read with `hmi_read_unified_object`; an empty item path selects the screen itself. Preview with `hmi_preview_unified_edits`, supplying its fingerprint, exact old values, property names and culture (empty for scalars). Use only returned editable fields. Simple single-run rich text is supported while retaining styling. Multi-run/complex text, dynamic fields and dynamized properties remain inspection-only. The fingerprint covers the returned property snapshot and binding names. Apply an authorized preview with `hmi_apply_unified_edits`.

Review the returned diff against the user's requested changes. When those changes are already authorized, apply the matching plan ID and candidate SHA-256. If authority or scope is missing, present the concrete preview and request only the missing decision. Do not ask the user to approve an action they already authorized.

An apply updates the open engineering project and verifies native readback in a Siemens transaction. It does not save. Run `hmi_compile` after applying; report errors and warnings. Save with `tia_save_project` only within the user's authorization to save the entire project, since it includes edits already present from other editors. Resolve compile errors before saving unless the user explicitly requests saving the work in progress. Retain the artifact directory for original/candidate XML or JSON snapshots and the apply report.

On a stale fingerprint, re-read and create a new preview. On an uncertain write or transport failure, inspect the current HMI before proceeding; never replay a consumed plan or assume rollback. Native import/readback, compile, save, and device/runtime acceptance are distinct results. The tools do not download to an HMI or control runtime.

For setup and build-specific version requirements, read [the bundled guide](../../README.md).
